# 沐龙量化系统 · 完整维护教程


---

## 〇、先记住三条铁律（最重要）

1. **正式服禁止「热更代码」**  
   不要在服务器上改 `.py`、不要用 `docker cp` 覆盖程序文件、不要跑 `hotfix` 脚本。  
   半套代码会导致「页面新、逻辑旧、报错莫名」。

2. **本地改完 → 提交推送 → GitHub 一键 Deploy**  
   这是唯一正规上线路径。

3. **密钥永远不要写进文档、不要发聊天、不要提交到 Git**  
   钉钉 Webhook、交易所 API Key、数据库密码只放在服务器上的 `.env` 或私密配置里。

## 一、这套系统是干什么的（一句话）

**沐龙量化交易平台**：网页上看策略回测与行情、控制实盘自动交易、监控币种/新闻、接收 TradingView 信号并推到钉钉群，外加 A 股 AI 做 T、加密信号评分等辅助功能。

你可以把它想成三层：

| 层 | 你看到的 | 实际跑在哪 |
|----|----------|------------|
| 网页 | 浏览器打开的界面 | 正式服 Nginx → 8100 端口 |
| 大脑 | API / 策略 / 监控 | Docker 容器 `backpack-api` 等 |
| 信使 | 钉钉群消息、TradingView 报警 | `tradingview_bot`（5001）、钉钉 Stream 机器人容器 |

## 四、日常「改参数」该改哪里？（对照表）

不懂代码时，**优先在网页改**；网页没有的再找配置文件或 `.env`。

| 你想改什么 | 在哪里改 | 改完要做什么 |
|------------|----------|--------------|
| 自选股票关键词、新闻源勾选、轮询秒数 | 网页「自选多源快讯」 | 保存 / 保存并启动 |
| 吴说/方程式监控币（AAVE、UNI、HYPE…） | 配置里的 `source_keywords`（默认已写好）；或让懂的人改 JSON | 保存配置或 Deploy 后生效 |
| 实盘保证金、杠杆、止盈止损%、保本/锁利 | 网页「策略交易」启动/编辑弹窗 | 保存并启动实例 |
| A股 AI 做 T 周期（5/15/30） | 网页「A股AI自适应」 | 保存任务设置 |
| A股 AI 说话风格纠偏 | 钉钉引用卡片 + @Stream 机器人 → 网页「待确认」→「刷新并生效风格」 | 不要只发自定义 Webhook |
| 钉钉收不到（关键词） | 服务器 `.env` 里的 `DINGTALK_KEYWORD`（多为「提醒」）；A 股群有时是「信号」 | 改 `.env` 后重启相关容器/进程 |
| 钉钉 Webhook 地址 | `.env` 或 `stock_news_alert_config.json` 的 `dingtalk_webhook` | 重启或保存配置；**不要泄露到公开仓库** |
| TradingView 某个策略 ID 推到哪个群 | 代码 `tradingview_bot.py` 的映射表 | **必须 Deploy + 重启 5001**，禁止服务器直接改文件 |
| 数据库密码、代理、交易所 Key | 仅服务器 `/opt/backpack-quant/.env` | `docker compose up -d` 重建相关服务 |
| 任何程序逻辑 / 页面文案 | 本地改代码 | commit → push → Deploy |

## 五、本地电脑怎么跑起来（开发机）

> 维护正式服不一定要每天本地跑；但「改完要验证」时需要。

### 5.1 用 Docker（更接近正式服）

1. 安装 Docker Desktop（Windows）。  
2. 打开项目文件夹（本仓库根目录）。  
3. 复制环境模板：把 `deploy/env.example` 复制成根目录 `.env`，按注释改数据库等（**不要用正式服真密钥到聊天里对**）。  
4. 先构建前端：

```bash
bash deploy/build-frontend.sh
```

5. 启动（本地带 MySQL 示例）：

```bash
COMPOSE_PROFILES=local-mysql docker compose up -d --build
```

6. 浏览器打开：`http://127.0.0.1:8100`，健康检查：`http://127.0.0.1:8100/api/health`

### 5.2 只改网页时

```bash
cd backpack_quant_trading/frontend
npm install
npm run dev
```

改完要上线前必须：

```bash
npm run build
```

构建失败 = **不能 Deploy**。

## 六、本地代码更新后，云服务器怎么部署（必背流程）

### 6.1 正确流程（图解）

```
① 本地改好并自己点一点验证
        ↓
② Git 提交（commit）→ 推送到 GitHub（push）
        ↓
③ 打开 GitHub → Actions → 「Deploy to Prod ECS」→ 手动 Run
        ↓
④ 等绿勾成功
        ↓
⑤ SSH 上服务器做验收（第七章）
```

### 6.2 GitHub 上怎么点（不会命令行也能做）

1. 浏览器打开本仓库 GitHub 页面。  
2. 上方 **Actions**。  
3. 左侧找 **Deploy to Prod ECS**。  
4. 右侧 **Run workflow**：  
   - `action` 选 **deploy**（日常发版）  
   - 或 **list**（看服务器上有哪些版本）  
   - 或 **rollback** + 填写版本号（回滚）  
5. 等跑完，点进这次运行看是否全绿。

### 6.3 绝对不要做的事

| 禁止 | 为什么 |
|------|--------|
| 在服务器用记事本改 `.py` | 下次 Deploy 会被覆盖或半套错乱 |
| `docker cp` 把本地 `.py` 拷进容器 | 同上，已多次出事故 |
| 跑 `deploy/hotfix-*.sh` | 仓库政策禁止 |
| 在 ECS 上 `npm install` 编前端 | 小内存容易卡死 / OOM |

### 6.4 可以做的「非代码」运维

- 查日志、查健康检查  
- **经负责人同意**后改正式服 `.env`（Webhook、密钥）  
- **经负责人同意**后导入策略 CSV 数据（不是改程序）

### 6.5 回滚（发坏了怎么退）

在 Actions 同一 workflow：

- `action=list` 先看有哪些版本  
- `action=rollback`，填 `rollback_version`（形如 `20260817-090015-a1b2c3d`）

回滚也是正规发布，**不是**热更。

## 七、Deploy 之后怎么验收（复制粘贴清单）

SSH 登录正式服后执行：

```bash
# 1) 三个关键容器在不在
docker ps --format 'table {{.Names}}\t{{.Status}}' | grep -E 'backpack-(api|webhook|dingtalk-agent)' || true

# 2) API 活着吗
curl -sf http://127.0.0.1:8100/api/health || curl -sf http://127.0.0.1:8100/health || true

# 3) TradingView 钉钉转发 5001
ss -tlnp | grep -E '5001|5002'
curl -sf http://127.0.0.1:5001/health

# 4) 钉钉 Stream 最近日志
docker logs backpack-dingtalk-agent --tail 30 2>&1 | tail -30

# 5) 若改了 A股 AI，再看 api 日志关键词
docker logs backpack-api --tail 50 2>&1 | grep -iE 'a.share|a_share|startup' | tail -20
```

**浏览器**：强制刷新（Ctrl+F5）相关页面，看文案/功能是否变新。

**按改动冒烟：**

| 这次改了啥 | 你怎么试一下 |
|------------|--------------|
| 前端页面 | 硬刷新，点进对应菜单 |
| TradingView 新策略 ID | 发一条带该 id 的测试 webhook，看对应钉钉群 |
| A股 AI | 网页启动任务；看有没有买卖推送（观望不推） |
| 自选快讯 / 吴说方程式 | 探测数据源；看关键词是否仍勾选 |

汇报可写成：

```text
Deploy 验收
- Actions：成功 / 失败（贴链接）
- 容器：api / webhook / dingtalk-agent 状态
- 8100 health：
- 5001 health：
- 冒烟结果：
- 尚未验证：
```

## 八、功能报错速查表（先对号入座）

### 8.1 网站 / API

| 现象 | 可能原因 | 你怎么做 |
|------|----------|----------|
| 网页打不开 / 白屏 | Nginx、8100、容器挂了；或前端 dist 没打进镜像 | 查 `docker ps`、`curl 8100/api/health`；确认最近 Deploy 成功；硬刷新 |
| 登录不上 | 账号/鉴权配置；API 挂了 | 先确认 health；再找有权限的人查 `.env` 鉴权相关项 |
| 页面很旧 | 浏览器缓存或 Deploy 未带上新 dist | Ctrl+F5；确认 Actions 构建前端成功 |

### 8.2 钉钉

| 现象 | 可能原因 | 你怎么做 |
|------|----------|----------|
| 完全没消息 | Webhook 错、机器人关了、关键词不匹配 | 网页点「测试钉钉」；检查安全词是否为「提醒」或「信号」 |
| 有的群有、有的没有 | TV 的 id→群映射错 | 查 `tradingview_bot` 映射（需懂的人 + Deploy） |
| A股 AI 纠偏不生效 | 没用「引用卡片 + @Stream 机器人」 | 按正确方式回复；看 `backpack-dingtalk-agent` 日志 |
| 测试机和正式机抢机器人 | 两台用了同一个 Stream Client | 测试机关掉 dingtalk-agent 或换 Client |

### 8.3 自选多源快讯 / 吴说 / 方程式

| 现象 | 可能原因 | 你怎么做 |
|------|----------|----------|
| 探测金十失败 | 代理干扰国内源 | 看日志；确认不要错误强制代理（相关 env：`STOCK_NEWS_*_PROXY`） |
| 吴说/方程式没勾选 | 配置未启用 | 网页数据源勾选 `wublock` / `bwenews` 并保存 |
| 加密新闻不推 | 正文没命中 AAVE/UNI/… 等词 | 正常；只有命中才推。可改 `source_keywords` |
| 股票新闻太吵 | 影响面词太宽、未开「仅重要」 | 勾选「仅重要快讯」、收紧影响面关键词 |

### 8.4 策略交易（实盘）

| 现象 | 可能原因 | 你怎么做 |
|------|----------|----------|
| 输入框删光变成 0 | 旧前端 bug | 已修版本 Deploy 后：删空应是空白；提交时用默认值 |
| 止盈止损重复挂很多单 | 旧逻辑「启动补挂」+ 手动单也被挂 | 已修：仅策略自己开仓才挂；需 Deploy |
| 手动开的仓也被挂止盈止损 | 同上 | Deploy 新版本后不应再挂；旧残留单可在交易所手动撤 |
| 开仓失败「余额不足」 | 保证金设太大 | 在策略交易里把保证金调小 |
| 实例停了又自己起来 | 看是否有自动恢复；查日志 | `docker logs backpack-api` |

### 8.5 A股 AI 做 T

| 现象 | 可能原因 | 你怎么做 |
|------|----------|----------|
| 买了十几秒就卖、钉钉推两次 | 同根 K 线扫了两次 | 新版本有「同桶去重 + 同 bar 不卖」；需 Deploy |
| 观望也推钉钉 | 旧逻辑 | 新版本只推买入/卖出 |
| 乱止盈止损 | 程序化止盈止损开关 | 当前设计默认关程序化止盈止损，只跟模型买卖 + 尾盘强平规则 |

### 8.6 TradingView

| 现象 | 可能原因 | 你怎么做 |
|------|----------|----------|
| 报警不进群 | 5001 挂了；映射 id 不对；Webhook URL 错 | `curl 5001/health`；重启宿主机 bot（**不要** docker cp 改代码） |
| 下单没反应 | webhook 服务 8005 / 密钥 | 查 `backpack-webhook` 日志与 `.env` 的 webhook 密钥 |

### 8.7 部署 / 代理 / 数据库

| 现象 | 可能原因 | 你怎么做 |
|------|----------|----------|
| Actions 红了 | 前端 build 失败、SSH 失败 | 看 Actions 日志；先本地 `npm run build` |
| 容器里访问外网失败 | 代理写成了 `127.0.0.1` | 容器应用 `host.docker.internal` 或宿主机网关 + 7891 |
| MySQL 挂 / OOM | 内存不够 | 降 worker、加 swap；找运维看主机内存 |

## 十、策略「数字不对」——导入交易 CSV（数据运维，不是改代码）

适用：长盈叁号 ETH、创新药 159570 等**回测成交表**要更新。

### 10.1 原则

- 可以：把 CSV 拷到服务器 → 拷进容器 → 调导入接口  
- 不可以：顺便改 `.py` 源码  

### 10.2 ETH 阿尔法示例（在能 SSH 的机器上）

1. 本地改好仓库根目录文件：`阿尔法策略_ETHUSDT_2H_交易数据.csv`  
2. 上传到服务器 `/opt/backpack-quant/`  
3. 拷进 API 容器并导入：

```bash
docker cp '/opt/backpack-quant/阿尔法策略_ETHUSDT_2H_交易数据.csv' 'backpack-api:/app/阿尔法策略_ETHUSDT_2H_交易数据.csv'
curl -sS -X POST http://127.0.0.1:8100/api/strategy/alpha-eth-2h/import-csv
curl -sS http://127.0.0.1:8100/api/strategy/alpha-eth-2h/overview
```

4. 浏览器刷新「长盈叁号·ETH」页核对笔数与累计收益。

### 10.3 A 股策略 CSV

常见文件名：`159570.csv`、`300308.csv` 等，放在项目约定目录后走：

- `POST /api/strategy/a-share/import-all`  
或专用工具脚本（让懂的人执行一次即可）。

**注意：** 导入会按策略**整表替换**该类交易，导入前确认 CSV 是完整账本。
