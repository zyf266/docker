# 沐龙量化系统 · 完整维护教程


> **密钥、Webhook、数据库密码不要写进本文档、不要发聊天、不要提交 Git。**

## 〇、先记住三条铁律（最重要）

1. **正式服禁止「热更代码」**  
   不要在服务器上改 `.py`、不要用 `docker cp` 覆盖程序文件、不要跑 `hotfix` 脚本。  
   半套代码会导致「页面新、逻辑旧、报错莫名」。详见 `docs/deploy-policy-no-hotfix.md`。

2. **本地改完 → 提交推送 → GitHub 一键 Deploy**  
   这是唯一正规上线路径（Actions → **Deploy to Prod ECS**）。

3. **密钥永远不要写进文档、不要发聊天、不要提交到 Git**  
   钉钉 Webhook、交易所 API Key、数据库密码只放在服务器上的 `.env` 或私密配置里。

## 一、这套系统是干什么的（一句话）

**沐龙量化交易平台**：网页上看策略回测与行情、控制实盘自动交易、监控币种/新闻、接收 TradingView 信号并推到钉钉群；另有 **Portal 产品站**（普通用户看绑定账面账户 / 观察库）、A 股 AI 做 T、加密信号评分等。

| 层 | 你看到的 | 实际跑在哪 |
|----|----------|------------|
| 网页（管理后台） | 登录后左侧菜单 | Nginx → `backpack-api:8100` |
| 网页（产品站 Portal） | 普通用户 `/portal` | 同上 API |
| 大脑 | API / 策略 / 监控 | Docker `backpack-api` 等 |
| 信使 | 钉钉、TradingView | `tradingview_bot`（宿主机 **5001**）、`backpack-webhook`（**8005**）、`backpack-dingtalk-agent` |

## 三、账号与权限（别人最常问）

### 3.1 角色一览

| role | 谁有 | 能干什么 |
|------|------|----------|
| `user` | 网页注册；Portal 连接手机号自动建号 | 产品站 `/portal`；看自己绑定的 `ba_*` 账面；观察库**只读**（模板用户，默认 `john666`） |
| `superuser` / `admin` / `root` | **只能 CLI 创建或提权**（三者权限等价） | 管理后台全功能；账面增删改；改观察库；策略交易等 |

前端判断：`superuser` | `admin` | `root` → 管理员。  
后端：`backpack_quant_trading/api/deps.py` → `is_admin_role`。

**注意：**

- 网页「注册」永远是 `user`，**不会**变成管理员。
- 改角色后用户需 **重新登录**（JWT 里带了旧 role）。
- Portal「连接账户」若填新手机号，会建 `user`，默认密码 **`123456`**（让用户尽快改密）。

### 3.2 正式服：用户管理命令（复制即用）

所有命令在 **SSH 上**执行，进 `backpack-api` 容器：

```bash
# 进入容器（工作目录已是 /app）
docker exec -it backpack-api bash
```

#### 列出全部用户

```bash
python -m backpack_quant_trading.tools.create_admin_user --list
```

或一行不进交互壳：

```bash
docker exec backpack-api python -m backpack_quant_trading.tools.create_admin_user --list
```

#### 新建管理员

```bash
docker exec backpack-api python -m backpack_quant_trading.tools.create_admin_user \
  --username '新管理员名' \
  --password '至少6位密码' \
  --role superuser
```

`--role` 可选：`superuser` | `admin` | `root`（权限相同，按习惯选）。

#### 把已有账号提权为管理员（不改密码）

```bash
docker exec backpack-api python -m backpack_quant_trading.tools.create_admin_user \
  --username '已有用户名' \
  --set-role \
  --role root
```

（`--promote` 与 `--set-role` 等价，旧文档写法仍可用。）

#### 把管理员降为普通用户

```bash
docker exec backpack-api python -m backpack_quant_trading.tools.create_admin_user \
  --username '用户名' \
  --set-role \
  --role user
```

#### 重置密码（不改角色）

```bash
docker exec backpack-api python -m backpack_quant_trading.tools.create_admin_user \
  --username '用户名' \
  --reset-password '新密码至少6位'
```

#### 同时改角色 + 改密码

```bash
docker exec backpack-api python -m backpack_quant_trading.tools.create_admin_user \
  --username '用户名' \
  --set-role --role superuser \
  --reset-password '新密码至少6位'
```

#### 观察库模板用户（普通用户只读谁的配置）

- 默认用户名：`john666`（须为管理员账号，且其观察库已配好）。
- 改模板：在正式服 `.env` 增加/修改后重建 api：

```bash
# /opt/backpack-quant/.env
PORTAL_WATCHLIST_TEMPLATE_USER=john666
```

```bash
cd /opt/backpack-quant
docker compose up -d backpack-api   # 或按现网 compose 服务名重启 api
```

### 3.3 权限相关故障

| 现象 | 处理 |
|------|------|
| 提权后仍进产品站 / 按钮还是灰的 | 退出登录再登；清站点 localStorage 后重登 |
| 普通用户看不到账面卡 | 管理员在 Portal「连接」时用手机号绑定了 `ba_*`；查 `portal_book_accounts.owner_user_id` |
| 普通用户改不了观察库 | 设计如此（只读）；改 `john666`（管理员）的观察库即可同步展示 |
| `create_admin_user` 报连不上库 | 确认容器内 `DB_HOST` 等与 `.env` 一致；`docker logs backpack-api --tail 50` |

| 能力 | 管理员 | 普通用户 |
|------|--------|----------|
| 添加/删除账面账户、改本金 | ✅ | ❌ |
| 添加观察库标的 / 状态与交易配置 | ✅ | ❌（只读模板库） |

**账面 Webhook（无端口，经 Nginx 80）：**

```text
http://47.110.57.118/api/portal/book-trade-webhook
```

PowerShell 测试（勿用乱转义的 `-d \"...\"`，用 JSON 文件最稳）：

```powershell
cd "C:\Users\A1\PycharmProjects\PythonProject - docker版本\backpack_quant_trading"

# 开仓
curl.exe -X POST "http://47.110.57.118/api/portal/book-trade-webhook" `

# 平仓
curl.exe -X POST "http://47.110.57.118/api/portal/book-trade-webhook" `
  -H "Content-Type: application/json" --data-binary "@tmp_book_close.json"
```

JSON 示例（`tmp_book_open.json`）：


## 七、代码更新后怎么上正式服

```
① 本地改好并验证
        ↓
② Git commit → push GitHub
        ↓
③ Actions → 「Deploy to Prod ECS」→ Run workflow（action=deploy）
        ↓
④ 等绿勾
        ↓
⑤ SSH 验收（第八章）
```

| 禁止 | 为什么 |
|------|--------|
| 服务器上改 `.py` / `docker cp` | 半套版本，下次 Deploy 更乱 |
| `deploy/hotfix-*.sh` | 仓库政策禁止 |
| 在 ECS 上 `npm install` 编前端 | 小内存易 OOM |

**允许的非代码运维：** 查日志、health；**经负责人同意**改 `.env`、导入 CSV、第三章改用户权限。

**回滚：** Actions 同一 workflow → `action=list` 看版本 → `action=rollback` + `rollback_version`。

## 九、功能报错速查

### 9.1 网站 / API

| 现象 | 可能原因 | 你怎么做 |
|------|----------|----------|
| 打不开 / 白屏 | Nginx、8100、容器挂；dist 未进镜像 | `docker ps`、`curl 8100/api/health`；确认 Deploy；硬刷新 |
| 登录不上 | 密码错；API 挂；角色异常 | health → 第三章 reset-password / list |
| TV 必须带 `:8100` 才通 | 80 未转发 `/api/` | 查 `backpack-api-80.conf`；`nginx -t`；reload |

### 9.2 钉钉 / TV / 实盘 / A股 / 快讯

| 现象 | 处理要点 |
|------|----------|
| 完全没钉钉 | 测 Webhook；关键词「提醒/信号」；`5001/health` |
| A股纠偏不生效 | 必须「引用卡片 + @Stream 机器人」 |
| 测试机抢 Stream | 关测试机 `dingtalk-agent` 或换 Client |
| 吴说/方程式不推 | 勾选 `wublock`/`bwenews`；正文须命中币种词 |
| 开仓失败余额不足 | 策略交易里调小保证金 |
| 5001 挂了 | 宿主机重启 `tradingview_bot.py`（**禁止** docker cp 改代码） |

## 十六、应急小抄

1. 网站挂了 → `curl 8100/api/health` + `docker ps`  
2. 钉钉没了 → Webhook + 关键词 + `5001/health`  
3. 登录/权限不对 → `--list` / `--set-role` / `--reset-password`，再重新登录  
4. TV 账面不通 → `curl` 无端口 `/api/health`；查 `backpack-api-80.conf`  
5. 上新功能 → 本地验证 → push → Actions Deploy → 第八章  
6. 回退 → Actions rollback，**不要热更**
