# 一、项目经验（我会这样问你）

### Q1. 挑一个最能证明你「AI 赋能落地」的项目，讲 3 分钟

**参考答：**  
**S：** 需要把 LLM/Agent 嵌进真实业务流程，而不是演示聊天。  
**T：** 我负责从 0 到 1：信号进 → 评分/路由 → 钉钉触达 → 可配置开关与发布规范。  
**A：**  
- 选型：什么路径用固定 Workflow，什么用 Agent + Tool Calling；敏感操作强制确认落库。  
- 部署：多进程隔离（交易/评分旁路）、Docker + CI 发布，禁止生产热更。  
- 赋能：给业务方 Webhook 样例、dry-run、观察库状态说明；沉淀文档与验收清单。  
**R：** 形成可运维闭环；问题先止血再复盘进规范。  
**收尾：** 到贵司我会把同一套「场景→工具→规范→培训→指标」迁到门诊/药房等业务线。

### Q2. 你推过哪些 AI 产品？怎么做选型？

**参考答：**  
用过/落地过：大模型 API（如 DeepSeek）、向量库 RAG、钉钉机器人、TradingView 信号侧自动化。  
选型看四件事：**业务适配、数据出域风险、成本、可集成性（API/账号体系）**。  
先小范围试点（1～2 个场景），有渗透率和主观效率反馈再扩面；不适合就换或降级为「人工+模板」。

### Q3. Prompt / Agent 你怎么保证稳定、可控？

**参考答：**  
Prompt 模板化 + 少样本；工具白名单；资金/改数类必须 **confirm**。  
Agent 用确定性路由（分析/风控/执行），避免多 Agent 乱聊。  
线上看失败率、超时、bad case 回流改模板——和贵司「持续优化 AI 流程」一致。

### Q4. 有没有失败项目？你怎么复盘？

**参考答：**  
早期想一次做全功能，联调期需求变、返工多。  
后来固定：**MVP → 演练/dry-run → 正式开关 → 度量**。  
失败会写成规范（例如禁热更），避免同一类事故。赋能类同理：先一个科室跑通手册和案例，再全员推广。

### Q5. 你没医疗行业经验，凭什么胜任？

**参考答（诚实+迁移）：**  
医疗业务流程我需要入职后跟门诊/药房同学学。  
可迁移的是：① 把业务语言译成工具配置与 Prompt；② 安全与权限意识（密钥、最小化权限、审计）；③ 跨部门培训与文档；④ Python/低代码自动化补齐重复劳动。  
医疗数据合规我会严格按公司制度，不擅自接外部模型处理敏感病历。

### Q6. 举一个你用 Python / 自动化提效的例子

**参考答：**  
量化侧用脚本做指标缓存、批量配置、发布验收；商城侧 Tool Calling + 确认落库。  
到岗后可对「重复填报、汇总、通知」做脚本或低代码（如定时拉取用量、自动发周报），先征求业务同意与安全评审。

# 二、跨部门沟通（JD 高频）

### Q7. 怎么给「门诊医生 / 药房」这类非技术同事做 AI 培训？

**参考答：**  
不讲模型原理，讲 **三步会用**：打开哪里 → 复制哪套话术/模板 → 结果怎么检查。  
材料：一页纸手册 + 3 个本科室案例 + 禁忌清单（什么不能喂给 AI）。  
现场：他们的真实工单演示；会后建答疑群，我做第一响应人。

### Q8. 业务说「AI 不好用」，你怎么处理？

**参考答：**  
先复现：是账号、网络、Prompt、还是预期不对。  
若是预期：一起改成功标准（例如「草稿 70 分可改」而不是「一次成终稿」）。  
若是工具：记 bad case，改模板或换工具；给临时人工兜底，不让业务空窗。  
同步 CIO/负责人的是 **问题分类 + 影响面 + 下一步日期**，不是甩锅。

### Q9. 研发说「排期紧，接不了 API」，业务又催，你怎么对齐？

**参考答：**  
拆成选项：  
- A：先 SaaS/账号级能力，不接系统（本周可用）；  
- B：只做只读 API / Webhook（工期短）；  
- C：深度编排（进迭代排期）。  
用一页纸写清依赖、风险、谁验收，拉共同上级 10 分钟拍板。我推进落地，不站队吵。

### Q10. 如何把「技术黑话」翻译成业务语言？（举例）

**参考答：**  
不说「Agent Tool Calling + RAG」，说：「员工用自然语言提问，系统按规定查内部资料并生成可编辑草稿，关键操作仍要人点确认。」  
不说「禁热更走 CI」，说：「改动必须走审批发布，保证能回滚，避免线上直接改坏。」

### Q11. 敏感医疗/商业信息，你怎么定使用规范？

**参考答：**  
默认：**最小必要、禁止把病历/身份证/完整处方贴进公网模型**；能脱敏就脱敏；企业版/私有化优先。  
文档写清红线 + 抽查；违规有上报路径。我过往对密钥 RSA、日志脱敏、确认落库是同一套安全意识。

### Q12. 跨部门冲突：市场要「全员开通」，信息安全要「先控权限」，你站谁？

**参考答：**  
不站人，站风险：先 **试点账号 + 分级权限**，出渗透率与事故为零的数据，再扩面。  
给双方可见的里程碑：试点名单、培训完成率、开通批次。

# 三、项目管理能力

### Q13. 如果让你 90 天推动公司 AI 赋能，你怎么拆？

**参考答：**  
- **D0–15**：摸底（现有工具、痛点访谈门诊/药房/职能/市场各 2～3 人）→ 选型短名单 → 安全红线草案。  
- **D16–45**：选定 1～2 个高价值场景试点（如病案草稿辅助、药房咨询话术、周报生成）→ 手册+培训 → 用量看板。  
- **D46–90**：复盘效率（耗时对比/满意度）→ 扩 1～2 科室 → 与研发排 API/Agent 需求池 → 向 CIO 汇报渗透率与下一步预算。  
每阶段有验收勾选，延期提前说并砍范围。

### Q14. 怎么衡量「赋能是否有效」？

**参考答：**  
过程：开通率、周活、场景使用次数、培训覆盖。  
结果：单任务耗时对比、返工次数、业务满意度（简短问卷）。  
不编造数字；没有基线就先建基线再对比。

### Q15. 多需求并行，你如何排优先级？

**参考答：**  
**影响面 × 合规风险 × 实现成本**。  
安全与数据红线优先；其次「高频重复劳动」场景；锦上添花的演示往后排。  
加塞时问：「插队则原里程碑延哪条？」逼出显式取舍。

### Q16. 你如何做风险与质量门禁？（结合工程习惯）

**参考答：**  
试点开关、回滚方案、权限分级；发布可追溯。  
AI 输出当「草稿」默认，关键业务节点人工确认。  
问题：止血（关能力/降级）→ 定位 → 复盘进规范。

### Q17. 直接向 CIO 汇报，你平时怎么同步进度？

**参考答：**  
三句话：**结论绿黄红 → 关键事实（渗透/阻塞）→ 要什么决策（预算/排期/政策）**。  
不报流水账；风险提前说。

### Q18. 你带过团队吗？这个岗要「推动各部门」算管理吗？

**参考答：**  
我更多是事项 Owner：拆任务、定验收、盯闭环，跨角色协作强于带编制团队。  
赋能岗的「管理」是 **影响力与项目制推进**，我会用试点数据说服部门负责人，而不是靠职位压人。

# 四、情景题（线下常临场）

### Q19. 上线培训次日大量账号登不上，门诊抱怨

**答：** 先止血（备用通道/人工模板）→ 定位（账号开通、SSO、并发）→ 定时同步业务 → 修通后补培训纪要与 FAQ。不争论「是不是 AI 的问题」。

### Q20. 某科室用 AI 写出带患者隐私的对外文案

**答：** 立即下架/撤回 → 按安全流程上报 → 加强脱敏检查与模板禁止项 → 该科室停用公网模型直至复训通过。

### Q21. CIO 问：为什么选 A 工具不选 B？

**答：** 对比表：场景匹配、数据驻留、权限、价格、集成、试点反馈。结论一句 + 附录表，表明可复测。
